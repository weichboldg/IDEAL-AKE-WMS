# v1.32.0 — IDEAL Teil 7: Schema-Inversion + Einweg-Migrationstor + Materialisierung + Lookup-Härtung

Umsetzung der freigegebenen Spec [[2026-07-29-standort-ideal-teil-7-spec]] (Epic, Etappen A–E) im
**bestehenden** Bündel-Worktree `feature/2026-08-07-ideal-teile-1-5` (gemeinsam mit Teilen 1–5,
v1.31.0). Ab Teil 7 wird die **Kern-Tabelle `ProductionOrders`** angefasst: aus der FA-Struktur
(Teil 1) werden Sub-FAs als echte Produktionsaufträge materialisiert und damit rückmeldefähig.
Aufgaben-/Umsetzungsnotiz [[2026-07-29-standort-ideal-teil-7]]. Architektur-Entscheidung:
[[0012-fa-hierarchie-einweg-migrationstor]].

**Querschnitts-Garantie:** additiv, AKE unverändert. Der Master `ProduktionsauftragHierarchisch` ist
Default **aus**; bei aus verhält sich alles wie vorher (`OrderNumber == SubOrderNumber`-Invariante
durch den Backfill, `SageMissingSince` durchgehend NULL). Neue Feature-/Sync-Schalter Default so, dass
AKE unberührt bleibt.

## Etappe A — Schema-Inversion (`fe7299b`)
- `ProductionOrder`: `SubOrderNumber` (NOT NULL, **unique**), `ParentSubOrderNumber` (nullable, echter
  Elternzeiger = Sage VaterFA), `SageMissingSince` (`datetime2 NULL`, Zeitstempel — **nicht** Bool,
  bewusst nicht `IsCancelled`). `OrderNumber` **nicht mehr unique** (Index-Tausch).
- EF-Migration `20260814105526_InvertProductionOrderHierarchy` (Up manuell korrigiert: nullable
  anlegen → Backfill `SubOrderNumber = OrderNumber` → NOT NULL → Index-Tausch, sonst bräche der
  Unique-Index auf befüllten AKE-Daten). Idempotentes **`SQL/90`** mit `COL_LENGTH`- +
  `sys.indexes`/`sys.key_constraints`-Guards (räumt Alt-Eindeutigkeit als `UQ_`-Constraint **und**
  `IX_`-Unique-Index ab). FreshInstall an beiden Stellen. Toter AgentJob
  `01_Import_Produktionsauftraege.sql` → `_archiv/`.
- **Daten-konvertierend** → DB-Backup vor Deploy zwingend. Serverseitige `sysjobs`-Prüfung als harte
  Deploy-Vorbedingung (kein aktiver Agent-Job schreibt `ProductionOrders`).

## Etappe B — Einweg-Migrationstor (`aed9cb5..39f7813`)
- **Master `ProduktionsauftragHierarchisch`** (ServiceSetting, Default false) als **Einwegtor**:
  Sperrbedingung datengetrieben `EXISTS(ProductionOrders WHERE OrderNumber <> SubOrderNumber)`.
- Reiner Planer `HierarchischeStrukturGuard.Evaluate(...)` (unit-getestet) + Durchsetzung als
  **Decorator** `GuardedServiceSettingRepository` auf `IServiceSettingRepository.UpsertAsync/DeleteAsync`
  — **einziger Choke-Point** über alle vier ServiceSettings-Schreibwege.
- Dedizierte Umschalt-Seite `HierarchieUmstellungController` + View (Bestätigungsmodal, Sperr-Anzeige,
  Runbook-Verweis). Generische `/ServiceSettings`-Maske zeigt den Master read-only; technischer
  Schreibversuch wird abgelehnt + protokolliert. Audit-SyncLog `HierarchieUmstellung`.
- Gecachter Anzeige-Zustand `HierarchischeStrukturStatus` (Refresh am Start; Umschalt-Seite refresht
  bei GET — cross-process-sicher) vs. Live-Schreibpfad. Runbook
  `docs/RUNBOOK-FA-HIERARCHIE-RUECKBAU.md` + README.

## Etappe C — Materialisierungs-Sync (`dc297d9..bc7e3d6`)
- Reiner `FaMaterializationPlanner.Plan(source, existing)` (unit-getestet) mit drei Sync-Regeln:
  (1) neuer Sub-FA → anlegen; (2) verschwunden → `SageMissingSince` setzen, **nie löschen**,
  selbstheilend beim Wiederauftauchen; (3) Umhängung → melden, nicht still übernehmen. **Empty-Source-
  Guard** (leere Struktur → nichts markieren).
- Orchestrator `FaMaterializationSyncService` (Service, gated auf Master, nach FA-Hierarchie-Sync):
  liest lokale `FaHierarchyNodes` (`SubFA != 0`), mappt int→string, EF-Apply mit **Erhalt der
  App-Felder**, **eine** Sammelmail pro Lauf (nur nicht-erledigte Vermisste). SyncLog `FaMaterialization`.
- **Mapping datenabhängig** (Wurzel `HauptFA==SubFA` → Hauptauftrag, Parent-Kette
  `child.VaterFA==parent.SubFA`, Node-Dezimal `NULL→0`) — am ersten echten Sage-Datenlauf zu bestätigen.

## Deploy-Risiken
- **DB-Backup vor Deploy zwingend** (Kern-Tabelle, daten-konvertierend, Migration SQL/90).
- Serverseitige `sysjobs`-Prüfung vor der Migration (kein Agent-Job schreibt `ProductionOrders`).
- Reihenfolge: Backup → Agent-Job-Prüfung → Windows-Service stoppen → Migration → Service-Neustart →
  Web-Deploy. Master bleibt nach Deploy **default aus** — die Umstellung ist ein bewusster späterer
  Schritt am Zielsystem.
- **Irreversibilität:** Etappe A invertiert das Schema unabhängig vom Master. Rückweg nur über das
  Runbook (Datenbereinigung außerhalb der App).
- Die 7 kritischen `OrderNumber`-Lookups (SageProductionOrderSql/SageImportService-UPDATEs) sind am
  AKE korrekt, am IDEAL deaktiviert — Umstellung ist Teil 8, bevor IDEAL einen aktiviert.

## Deploy-Umfang

- **Service:** ja (Materialisierungs-Sync, angepasster `FaZusatzinfoSyncService`).
- **Migration:** ja (SQL/90, daten-konvertierend).
