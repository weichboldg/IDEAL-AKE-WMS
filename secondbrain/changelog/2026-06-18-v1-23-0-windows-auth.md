# v1.23.0 — Windows-Authentifizierung + AD-Benutzer

- **Windows-SSO Auto-Login** via `WindowsAutoLoginMiddleware` (hinter AppSetting
  `WindowsAuthAktiv`, Default false): Domaenen-User werden ohne Formular angemeldet, jeder Fehler
  und jeder Nicht-Treffer fallen zum Formular durch. Logout setzt `NoAutoLogin` → Benutzerwechsel
  moeglich → [[0002-dual-auth-session-login-plus-windows-sso]].
- **Hosting-Korrektur:** `AddNegotiate()` → `AddAuthentication(IISServerDefaults.AuthenticationScheme)`
  — unter IIS in-process war `AddNegotiate()` falsch. Negotiate-Package entfernt, beide
  IIS-Auth-Modi bleiben aktiv.
- **`User.WindowsUserName`** als Login-Schluessel, **Migration 73**. Dieselbe Migration **droppt
  `Role.AdGroup`**: Rollen kommen ab jetzt nur noch explizit pro Benutzer →
  [[0006-rollenkonzept-statische-keys-mit-admin-wildcard]].
- **AD-Benutzer-Picker** liest die Mitglieder der `WindowsAuthBerechtigungsgruppe` live per LDAP.
- Neue AppSettings `WindowsAuthAktiv` und `WindowsAuthBerechtigungsgruppe`; neuer
  appsettings-Schluessel `Security:AdDomain` (`Security:AdGroupCacheMinutes` entfaellt).
- **Folge-Erweiterungen im selben Release:** Rolle `lagerbestellung` (**Migration 74**) +
  Artikelinfo-Kachel fuer `masterdata_read`; Lagerbestellungs-Druck spiegelt Spalten, Sortierung
  und Filter der GUI; FA-Abarbeitung `DefaultWorkplaceId` → `DefaultWorkbenches`
  (**Migration 75**, destruktiv) plus Spalten Bezeichnung 1/2; FA-AG-Erkennung im
  Aktivitaets-Protokoll aufgeschluesselt.
- LDAP- und IIS-Negotiate-Strecke sind **nicht** automatisiert testbar → Manual-UAT
  (`../../docs/TESTSZENARIEN.md` Kap. 40).
